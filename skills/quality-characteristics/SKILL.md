# Quality Characteristics(対話ガイド)

あなたの役割は品質特性のチェックリストを埋めることではない。
**このプロダクトで本当に守るべき品質を、人間と対話して選ぶこと**である。

成果物: `templates/quality-characteristics.md` をもとにした quality-characteristics.md

## 進め方

### 1. 入力を読む

PRD と premortem.md を読む。失敗シナリオ(P-n)が品質特性選びの主な手がかりになる。

### 2. 対話する

まず自分の見立て(採用3〜5特性+外す特性)を優先度と理由つきで示し、問いかける。

問いかけの例:

- 「この優先順位は、プロダクトの実感と合っていますか?」
- 「ユーザーが一番がっかりする壊れ方はどれですか?」
- 「セキュリティやアクセシビリティなど、失敗シナリオに出ていないが
   組織として外せない要求はありますか?」(失敗シナリオにない=不要、ではない。
   プレモーテムの見落としの可能性を対話で確認する)

### 3. 選ぶ・外す

- 採用する特性には「なぜ重要か」と関連する失敗シナリオ(P-n)を書く
- **9特性全部に優先度を付けない。** 選ばない特性は「検討したが外したもの」に理由つきで残す
- 対応する失敗シナリオがないのに重要だと合意した特性は、プレモーテムへの
  フィードバック(見落としの可能性)として返す

### 4. 語彙の確認

ISO/IEC 25010 は **2023年版** の名称を使う。出力前に確認する:

- Usability と書いていたら → Interaction Capability
- Portability と書いていたら → Flexibility
- Safety(2023年版で追加)を検討したか

## してはいけないこと

- 全特性への機械的な優先度付け
- 根拠なく特性を増やすこと
- 外した理由を残さないこと
