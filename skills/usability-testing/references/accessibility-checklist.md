# アクセシビリティ確認の出発点

アクセシビリティ要件があるときに引く。準拠基準(WCAGのバージョンとレベル)は
プロジェクトで決まるので、**まず「何にどのレベルで準拠するか」を確定させる**こと。

> 注意: WCAG本文との突き合わせは未実施。正式な適合判定に使う場合は
> 一次資料(w3.org)と専門家の関与を前提にすること。ここは対話の出発点である。

## 4原則(POUR)と代表的な確認

| 原則 | 意味 | 対話で確認する例 |
|---|---|---|
| 知覚可能(Perceivable) | 情報が知覚できる | 画像に代替テキストがあるか / 色だけで情報を伝えていないか / コントラストは十分か |
| 操作可能(Operable) | UIが操作できる | キーボードだけで全操作が完結するか / フォーカスの順序と見え方 / 時間制限に延長手段があるか |
| 理解可能(Understandable) | 情報と操作が理解できる | エラーメッセージは何をすべきか伝えるか / 入力例・ラベルがあるか / 挙動が予測可能か |
| 堅牢(Robust) | 支援技術で解釈できる | スクリーンリーダーで読み上げられるか / セマンティクス(見出し・ランドマーク)が正しいか |

## 適合レベルの目安

```text
A     最低限(これを満たさないと使えない人がいる)
AA    一般的な準拠目標(公的機関・多くの社内規程の水準)
AAA   最高水準(全面適用は現実的でないことが多い)
```

## 早く安く見つかる確認(開発中から)

- キーボードのみ(Tab / Enter / Esc)で主要導線を通す
- OSのスクリーンリーダーで主要画面を読み上げる
- 文字サイズを200%にして崩れ・欠落を見る
- グレースケール表示にして、色だけに依存した情報がないか見る

構造(セマンティクス・フォーカス管理)の問題は後から直すコストが大きい。
**アクセシビリティを最後に回さない**(usability-testing Skill の禁止事項)。
