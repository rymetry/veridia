# Testing with GenAI(対話ガイド)

このSkillは他と役割が異なる。特定のテスト領域ではなく、
**Veridiaの運用そのもの — AIと一緒にテスト成果物を作るという行為 — を律する**。

ai-testing との区別:

```text
ai-testing          テスト対象がAIを含む(プロダクトの検証)
testing-with-genai  テスト活動にAIを使う(道具としての規律)← このSkill
```

規律のうち毎回の対話で必須の3点(根拠の突き合わせ・機密の投入可否確認・
実施証跡をAIが書かない)は、**全Skillの「前提規律」節に焼き込み済み**である。
このSkillはその全文と出典を持つ。

## いつ使うか

- 生成AIをテスト業務へ導入する判断・ルール作りをするとき
- AIの出力(失敗シナリオ・観点・ケース)の信頼性に疑問が出たとき
- 各Skillの「前提規律」の背景・全文を確認したいとき

## 規律

### 1. AI出力を無検証で成果物にしない(最重要)

生成AIの主要な失敗は、ハルシネーション(存在しない事実)・推論誤り・バイアスである。

- AIが挙げた仕様・画面・API・制約は、**入力資料(PRD/Figma)との突き合わせで確認してから**成果物に載せる。Veridiaの「根拠」列はこのためにある
- 出力が妥当に見えることと正しいことは別。**説明責任を果たせない成果物は採用しない**
  (「なぜこの観点か」を人間が自分の言葉で説明できるか)
- もっともらしく網羅的なリストほど疑う(生成AIは「それらしい網羅」が最も得意)
- 欠陥タイプで確かめ方を変える: **事実の捏造は原文と突き合わせ、推論・計算は実行して
  確かめ、偏りは複数の観点で点検する**
- 成果物のどこをAIが生成し、誰が検証したかを説明できる状態を保つ(透明性)

### 2. データの扱いを先に決める

- 「このPRD・ソースコード・顧客情報を、この AIツールに入れてよいか」を
  **貼る前に**確認する(社内規程・ツールの利用規約・データの保存先)
- 判断に迷う情報は入れない。マスキングか要約で代替できないか先に考える
- 個人が勝手に未承認のAIツールを使う(シャドーAI)状態を作らない。
  使ってよいツールと用途をチームで明文化する

### 3. 非決定性に対処する

- 同じ依頼でも出力は毎回変わる。**重要な判断の根拠をAIの再実行に置かない**
- 採用した出力は成果物(Markdown)として固定する。「またAIに聞けば出る」は
  記録ではない
- 同一入力での再生成による「ゆらぎ」を、レビューの代わりにしない

### 4. 使いどころを選ぶ

| 向いている | 向いていない |
|---|---|
| 失敗シナリオ・観点の候補出し(人間が絞る前提) | 合否の最終判定 |
| 文書の構造化・表への整理 | 業務・組織の事情を要する判断 |
| 抜け漏れの指摘(壁打ち相手) | 根拠の捏造が致命的な箇所の単独作成 |
| テストデータ・バリエーションの生成 | 機密を含む情報の外部ツールでの処理 |

### 5. 導入・改善の対話

チームへの導入を検討するときの問い:

- 「どのテスト作業が一番時間を食っていますか? そこにAIは効きますか?」
- 「AIの出力を検証する時間を含めても、速くなっていますか?」
- 「AIが間違えたとき、誰が気づける体制ですか?」

## してはいけないこと

- AI出力の無検証コピー(根拠の確認を省くこと)
- 機密・個人情報を確認なしにプロンプトへ入れること
- 未承認ツールの黙認(シャドーAI)
- AIに実施記録・証跡を書かせて「実施済み」にすること(検証の捏造)
- 「AIが言ったから」を根拠として使うこと
