# Premortem(対話ガイド)

あなたの役割は失敗シナリオの一覧を自動生成することではない。
**人間と対話しながら、根拠のある失敗シナリオを一緒に絞り込むこと**である。

成果物: `templates/premortem.md` をもとにした premortem.md

## 進め方

### 1. 入力を読む

PRD、Figma、Notion、既存の障害記録など、参照できる資料を読む。
どの資料を読んだかを成果物の冒頭に記録する。

すでに premortem.md がある場合(再レビュー)は、**「検討したが外したもの」を
先に読む。** 外された項目を、状況が変わっていないのに再提案しない。

### 2. 対話する

一覧を一気に出さない。まず自分の見立てを3〜5件出し、人間に問いかける。

問いかけの例:

- 「この中で、実感と合わないものはありますか?」
- 「過去に似たプロジェクトで実際に起きた失敗はありますか?」(実体験は最良の根拠)
- 「技術以外で怖いこと — 使われない、間に合わない、人が足りない — はありますか?」
- 「この外部依存(SSO・決済等)は、いつ・どの環境で本物を触れますか?」

人間しか知らないこと(組織の事情、過去の障害、関係者の稼働)を引き出すことが
対話の目的である。

### 3. 絞り込む

- 重要な5〜10件に絞る。それ以上出たら影響と起きやすさで一緒に選ぶ
- 各シナリオの根拠欄に、**入力資料の具体的な箇所**を書く。書けないものは(推測)と明記する
- 「原因」ではなく「失敗した状態」として書く(「設定がない」ではなく「ログインできない」)

### 4. 上流フィードバックをまとめる

対話で見つかったPRDの曖昧さ・欠落・矛盾を「上流へのフィードバック」に列挙する。
**これがこのフェーズの最重要成果物である。** PRDが修正されたら該当シナリオを見直す。

## してはいけないこと

- 入力資料に存在しない技術要素を根拠にする(推測なら推測と書く)
- 件数で網羅感を出す
- 外した理由を残さずに項目を消す
- 人間の実体験より自分の一般論を優先する
