# Mobile Testing(対話ガイド)

あなたの役割は端末を並べることではない。
**「どの端末×OSを、どの環境条件で確認すれば十分か」を根拠をもって絞ること**である。

新しい成果物は作らない。既存の成果物の該当箇所に書き込む。

## いつ使うか

- プロダクトにモバイルアプリ(ネイティブ / ハイブリッド / モバイルWeb)が含まれるとき

## 進め方

### 1. 端末マトリクスを対話で絞る

- 「利用者の端末は把握できていますか?(社内配布端末か、BYODか、一般消費者か)」
- 「サポートするOSバージョンの下限はどこですか? それは誰が決めましたか?」
- 全組み合わせは不可能。**利用シェア上位+最古サポート端末+画面サイズの両端**が基本形。
  絞った根拠を test-plan.md に残す

### 2. モバイル固有の環境条件を観点に入れる

デスクトップのテストでは存在しない壊れ方を対話で確認する。

```text
ネットワーク   圏外→復帰、Wi-Fi↔モバイル切替、低速回線での操作
割り込み       着信、通知、アプリ切替、バックグラウンド放置→復帰
リソース       電池残量低下、ストレージ不足、省電力モード
端末機能       画面回転、文字サイズ変更、カメラ・位置情報の権限拒否
```

- 「操作の途中で電話が来たら、入力中のデータはどうなるべきですか?」
- 「権限を拒否した利用者には何が起きますか?」

### 3. 配布・更新の失敗シナリオ

- ストア審査(リジェクト)によるリリース遅延 → premortem.md へ(Delivery領域)
- 旧バージョンとサーバーの互換性(全員が即更新しない)
- 強制アップデートの要否と手段

### 4. 書き込む先

| 内容 | 書き先 |
|---|---|
| モバイル固有の失敗シナリオ(圏外・割り込み・審査遅延・旧版互換) | premortem.md |
| 端末マトリクスと絞りの根拠 / 実機・エミュレータの使い分け | test-plan.md / test-architecture.md |
| 環境条件の観点 | test-design.md |
| 端末×条件のケース(パラメーターの絞り方を適用) | test-cases.md |

## してはいけないこと

- 端末網羅を目的化すること(根拠のある絞りが仕事)
- エミュレータのみで「実機確認済み」とすること(差を記録して区別する)
- ハッピーパスを複数端末で繰り返すだけのテスト(端末を変える価値があるのは環境依存の観点)
- ストア審査・配布をテスト対象外とすること(リリースの一部である)
