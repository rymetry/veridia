## この文書の役割

テスト設計の観点(TD-n)を、実行できる粒度のケースに展開する。

- 1観点=1ケースとは限らない。必要な数だけ作り、**数を増やすことを目的にしない**
- 判定方法が「人の判断」の観点は、無理にケース化せず確認会・レビューとして書く
- **「ケースを書いた」と「検証した」は別物。** 実施列は必ず「未」から始める

## テストケース

| # | 対応 | ケース名 | 前提 | 手順 | 期待結果 | 実施 | 結果・証跡 |
|---|---|---|---|---|---|---|---|
| TC-1 | TD-1 | 例: 本番同等SAML設定でのログイン | 検証環境にSAML設定適用済み | 1. SSO経由でログイン<br>2. トップ画面へ遷移 | ログイン成功しトップ画面が表示される | 未 | — |
| TC-2 | | | | | | 未 | — |

- 手順が長い場合は `<br>` で改行する。表に収まらない前提・データは表の下に補足として書く
- 実施列: 未 / OK / NG / 保留。NG・保留は結果・証跡列に理由や課題へのリンクを書く
- 証跡はスクリーンショット・ログ等へのリンク
