## この文書の役割

テスト計画の各項目(TP-n)を、**何を確認すれば検証したことになるか**(テスト観点)へ
展開する。個々の手順・入力値まではここでは書かない(テストケースの仕事)。

## テスト観点

| # | 対応 | 確認する観点 | 判定方法 | 使った技法 |
|---|---|---|---|---|
| TD-1 | TP-1 | 例: 本番同等のSAML設定でログインが成功し、主要画面まで到達できる | 明確(成功/失敗が自明) | — |
| TD-2 | TP-1 | 例: 認証失敗時に失敗種別がログで識別できる | 明確 | エラー推測 |
| TD-3 | | | | |

判定方法は2択で書く:

- **明確** — 期待結果が事前に定義でき、成功/失敗が機械的に判定できる
- **人の判断** — 仕様の妥当性・使い勝手など、人が見て判断する必要がある

「人の判断」を無理に「明確」と書かない。判定できない観点に推測で
期待結果を作ることが、テストで最も危険な失敗である。

技法(境界値、状態遷移、デシジョンテーブル等)は、観点を導くのに使った場合だけ書く。
全部の観点に技法が要るわけではない。
